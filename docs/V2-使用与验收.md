# 第二版使用与验收

这是供验收的本地开发版本。未替换 main、未修改 Cloudflare 项目或正式环境、未发布正式站。当前 GitHub 集成在创建 redesign-v2 分支时返回 403，因此没有向远端推送代码。

## 启动和构建

安装 Node.js 22.12 或以上版本。在项目根目录打开终端：

```sh
npm install
npm run dev -- --port 4322
```

打开 http://localhost:4322/ja/，或 /en/、/zh-tw/。根路径 / 是语言选择页，不按 IP 跳转。

```sh
npm run build
node scripts/verify.mjs
npm run preview -- --port 4322
```

构建产物是 dist；没有服务器运行时，也不需要 Cloudflare adapter。

## 尚未做

## 新增一篇文章

1. 在 src/content/articles/ja/（或 en/、zh-tw/）新建 .md 文件。可复制同语言的 official-sources.md。
2. 修改 uid（全站唯一）、slug（英文短横线）、translationKey（同一篇的译文共用）、lang、title、summary、category。
3. 填写实际确认的来源、地区、日期，再编辑 Markdown 正文。没有官方发布时间的指南用 null；公告必须有可核实的官方日期。不要猜测。
4. 先设 status: draft。日期必须是含时区的 ISO 时间，例如实际发生时取得的 UTC 时间。审核完成后，经过站主确认才改 published。
5. 执行构建。缺少字段、未知地区、韩台服版本、重复 UID/路由、虚假未来日期和没有官方确认的维护完结记录会被拦截。

字段对应：category 为 patch（版本更新）、maintenance（维护）、enforcement（处罚）、event（活动）或 guide（编辑指南/攻略）；edition 必须 Global；region 支持 GLOBAL、ASIA、NA、EU、SA。

不要求配图。只有明确拥有许可时才填写 image，包含 src、alt、caption、sourceUrl、license（owned/permission/open-license）、licenseEvidence、width、height。文件放 public 内，使用 / 开头路径。新图片尽量提供合理尺寸，避免小卡片加载大图。记录许可证或授权依据；“网络公开”不是许可类型。

## 添加译文

把文章放到另一语言目录。保留 translationKey，修改 uid、lang，并人工完成标题、摘要和正文翻译。slug 可以相同也可以不同。不存在目标译文时，语言菜单会回退到目标语言分类并提示未翻译。draft 不会被当成已发布译文。

导航等固定文案在 src/i18n/ui.ts；品牌名称、正式域名、官方入口和邮箱在 src/config/site.ts；颜色、字号和布局在 src/styles/v2.css。

## 维护和处罚记录

维护文章需要 maintenance 对象：region、timeZone、startsAt、expectedEndsAt、status、actualEndsAt、completionSourceUrl。status 仅允许 scheduled、ongoing、extended、completed、cancelled、unconfirmed。只有 confirmed 实际结束时间和官方完成来源齐全才可 completed；经过预计结束时间不会自动改变状态。日文页面把时间换算为 JST，其他语言按记录的 IANA 时区显示，不用语言猜服务器所在地。跨夏令时换算由 Intl 完成。

处罚文章需要 enforcement 对象：reason、accountRestrictions、countingNote，并须填写 officialPublishedAt 和官方链接。每次公告独立记录，不自动合并为去重账号总数。

文章普通日期以 UTC 日历日期显示并按语言格式化，HTML time 的 datetime 保留完整时间戳。维护时刻独立换算。维护、处罚数据未实际核实前，不创建假记录。

未来的监控候选接口见 src/lib/editorial.ts，只定义数据契约，不运行抓取或后台任务。监控候选必须人工审核，不能直接转为已发布内容。

## 安全提交、验收和合并

本地 redesign-v2 基于 GitHub main 的 60922ac17469d20bf3e07b17c1db7aeadd134c5b。已保留原 main 的历史和改动前备份。GitHub 拒绝分支创建后，已停止所有远程写入。

1. 先验收本地三语言页面，再在本机 GitHub Desktop 或 Git CLI 登录具有仓库写入权限的账号。不要向聊天发送令牌。
2. 检查 git status、git diff 和当前分支是 redesign-v2。不要把 .git、node_modules、dist、.astro、.openai、.env、令牌或密钥提交到 GitHub。
3. 只提交开发分支。若远端 main 后续有变化，先 fetch 并在开发分支处理差异，禁止强推 main。
4. 推送 redesign-v2 后创建 PR。Cloudflare 若已允许该分支预览部署，可以使用它的独立 Preview URL；这不是生产 main。
5. 站主批准后才合并 PR；合并会自动触发当前 Pages main 的正式部署。本次未进行这一步。

源码压缩包以 package.json、astro.config.mjs、src、public 等为顶层。使用新克隆仓库时不要上传外层 outputs/aion2-site 目录，也不要上传 Git 内部历史文件。

当前本地项目尚未配置 GitHub origin。通过有写入权限的 GitHub Desktop 登录并添加已有仓库最适合初学者。熟悉命令行时，先用 git remote -v 核对；仅在没有 origin 时执行 git remote add origin https://github.com/3ukio/ukn-home.git，然后 git push -u origin redesign-v2。若已有 origin，应先核对地址，不要直接替换。推送必须在站主验收之后进行，main 的合并仍需单独批准。

若只使用压缩包手动恢复，请在克隆的 redesign-v2 分支中覆盖同名文件，并把根目录旧 pnpm-lock.yaml / pnpm-workspace.yaml 移至文档归档目录，避免与 npm 锁文件并存。不要覆盖当前仓库中其他人的后续修改。
